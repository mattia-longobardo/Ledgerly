# Phases 5–9: shared conventions for Codex

Every plan from Phase 5 onward (`2026-09-06-phase-5-funds.md` … `2026-09-06-phase-9-management-hardening.md`) starts with the line "Global Constraints: see `2026-09-06-phases-5-9-shared-conventions.md`" and lists only what is specific to that phase. **Read this file once per session, before the task you are executing.** It is binding on every task in every one of those plans.

These plans are deliberately shorter than the Phase 2–4 plans (each of those ran 7,000–13,000 lines and took several sessions to execute). They show the contracts, the tests and the tricky code, and for everything repetitive they name the file in the tree to copy. When a step says "mirror `src/modules/interests/infrastructure/memory-repositories.ts`", open that file and reproduce its structure for the new types — do not invent a different one.

## How to execute a plan with Codex

- One task per Codex run. Prompt shape: *"Implement Task N of `docs/superpowers/plans/<plan>.md` exactly as written. Read `docs/superpowers/plans/2026-09-06-phases-5-9-shared-conventions.md` first. Run every command the task lists, fix what fails, and commit with the message the task gives."*
- A task is done only when its own **Verify** block passes: `npm run typecheck` and `npm test` always; `npm run test:db:up && npm run test:integration` when the task adds or touches a `*.itest.ts`; `npm run openapi:generate` when it touches a route; `npm run build` in the exit-criteria task.
- Tick the task's checkboxes in the plan file as you go and commit the plan file with the code.
- Never skip an RLS integration test, a uniqueness proof, or the "delete the legacy code" steps to save time — the whole-branch reviews of Phases 3 and 4 found their worst defects precisely in those seams.
- If a task cannot be completed as written (a named file has moved, a signature differs), stop, write what you found under a `### Deviation` heading at the end of the task in the plan file, and fix the plan text before continuing. Do not silently adapt.
- For Claude Code executors the equivalent is `superpowers:subagent-driven-development`, one task per subagent, with the same verify blocks.

## Repository facts (verified 2026-09-06 on `main` at `6294194`)

- App root: `dashboard-app/`. All commands run from there unless a step says otherwise. `.env.example` lives at the repository root.
- Stack: Next.js 16.3, React 19, TypeScript 5.7 strict, Drizzle ORM 0.45 + drizzle-kit 0.31, Postgres 18, Zod 4, Hono 4 + `@hono/zod-openapi` 1.x, vitest 3, Playwright, NextAuth 5 beta (Authentik OIDC, JWT sessions). No shadcn: hand-rolled components in `src/components/ui/`, Tailwind v4, `uplot` charts (`src/components/chart/TimeSeriesChart.tsx`, `Sparkline.tsx`). Design rules in `BRAND.md` at the repo root.
- Migrations: `dashboard-app/drizzle/NNNN_name.sql`, highest today `0015_payroll.sql`. Generate with `npm run db:generate` (auto-named; rename the file), then append RLS and seed statements by hand, one per `--> statement-breakpoint`, exactly as `drizzle/0015_payroll.sql` does. Commit `drizzle/meta/_journal.json` and the snapshot with the `.sql`. Apply with `npm run db:migrate`. Each plan states its migration number; **verify it by listing `drizzle/*.sql` before generating.**
- RLS helpers `app_is_system()` and `app_current_user_id()` come from `drizzle/0009_platform_rls.sql`. Every user-owned table gets `ENABLE` + `FORCE ROW LEVEL SECURITY` and a policy `USING (app_is_system() OR user_id = app_current_user_id()) WITH CHECK (same)`. Child tables without `user_id` use an `EXISTS` join to the parent (see `payroll_components_owner` in `0015_payroll.sql`). Tables that mix global and per-user rows use four per-command policies (see `payroll_mapping_rules_*` in `0015_payroll.sql` and the comment above them explaining why one USING/WITH CHECK pair is unsafe for DELETE).
- Context: `withUserContext(db, { userId }, tx => …)` and `withSystemContext(db, tx => …)` in `src/platform/db/context.ts` open a transaction and `SET LOCAL app.user_id/app.role`. **Never nest them, never do network or filesystem I/O inside one.** A read on the pool-bound `db` with no context set returns zero rows silently — a guard written that way passes vacuously.
- Tests: unit `*.test.ts` next to the source, `npm test` (only `src/**/*.test.ts` is collected — a `.test.tsx` never runs, so components are tested through their pure helpers). Integration `*.itest.ts`, `npm run test:db:up && npm run test:integration`, harness `src/test/db.ts` (`testDb`, `resetDb`, `closeDb`), `src/test/principal.ts` (`testPrincipal`), `src/test/integration-setup.ts`. `resetDb()` truncates every table except `integration_providers`. Per-table RLS proofs live in `src/lib/db/<domain>-rls.itest.ts`; copy `src/lib/db/interests-rls.itest.ts`.
- Module shape (copy `src/modules/interests/` for a small module, `src/modules/payroll/` for a large one):
  - `domain/` pure functions, no I/O.
  - `application/ports.ts` (repository interfaces + `UseCaseDeps`), `application/deps.ts` (`export type { UseCaseDeps } from "./ports"`), `application/errors.ts` (`NotFoundError`, `VersionMismatchError`, `InvalidInputError`), one file per use case, curried `useCase(deps)(principal, …)`, first line `assertPermission(principal, "<code>")`, `deps.audit({...})` on every mutation.
  - `infrastructure/` Drizzle repositories (`drizzle-<name>-repository.ts`, explicit `user_id` predicates in addition to RLS), `memory-repositories.ts` (same contract; use `monotonicId()` and `normalizeScale()` from the interests module verbatim), `deps.ts` (`<module>Deps(tx, requestId?)` building the bag with `recordAudit` bound to `tx`), `repositories.itest.ts` proving the memory and Drizzle repositories agree on ordering, filters, conflict updates and uniqueness.
  - `api/schemas.ts` (Zod + `.openapi("Name")`), `api/routes.ts` (`register<Module>Routes(app, deps)`; import `ErrorResponseSchema` from `@/modules/accounts/api/schemas`, never redeclare it; duplicate only `errorResponse()`/`commonErrorResponses`/`toApiError()` as `src/modules/interests/api/routes.ts` does). Register in `registerAllRoutes` in `src/platform/http/app.ts`. Then `npm run openapi:generate` so `src/platform/http/openapi-drift.test.ts` stays green.
  - `ui/run.ts` (`runForPrincipal` + test seams, copy `src/modules/interests/ui/run.ts`), `ui/deps.ts` re-export, `ui/load-<page>.ts` loaders, client components. Server actions in `src/app/actions/<module>.ts` (copy `src/app/actions/expenses.ts`: `"use server"`, `FormData`, `runForPrincipal`, `revalidatePath`, `ActionResult` from `./types`).
- API conventions: base `/api/v1`; errors `{ error: { code, message, requestId, details? } }` via `ApiError` (`src/platform/http/errors.ts`, closed `ErrorCode` union — extend it in the same task if you need a new code); pagination `{ items, nextCursor }` with `cursor`/`limit ≤ 200`; mutations carry `version`, PATCH requires `If-Match` or body `version` via `parseExpectedVersion` (`src/platform/http/versioning.ts`), mismatch → `409 version_mismatch`; POSTs that create financial records get `app.on("POST", path, idempotency({ db: deps.db, now: deps.now }))` exactly like `src/modules/accounts/api/routes.ts:351`; cookie-authenticated unsafe requests must carry `X-Requested-With` (enforced globally, do not extend `PUBLIC_PREFIXES`).
- Permissions: codes in `src/platform/auth/permissions.ts` (`PERMISSIONS` + `ROLE_PERMISSIONS`); add new codes there and update `permissions.test.ts`. Capabilities in `src/platform/capabilities/resolve.ts` (pure) + `probes.ts` (real); navigation in `src/platform/capabilities/navigation.ts`; Home cards in `src/modules/home/cards.ts`.
- Jobs: name union `JobName` in `src/lib/contracts.ts`; registration in `src/platform/jobs/register-all.ts`; the admin panel `src/app/(app)/settings/admin/page.tsx` hard-codes `JOBS`/`JOB_LABEL` — a new job touches all three. **`withJobLock` (`src/lib/repo/jobs.ts`) holds a transaction for the whole job body; it is fixed in Phase 9 Task 1. Until then a job must not do network I/O inside it** — structure jobs as short transaction → I/O → short transaction, as `src/lib/jobs/payroll-ingest.ts` does.
- Money: Postgres `numeric` read as strings end to end. `numeric(16,2)` for money, `numeric(10,6)` rates, `numeric(16,6)` intermediates. Add with `addMoney` (`src/modules/payroll/domain/money.ts`) or `toCents`/`fromCents` (`src/lib/calc/money.ts`); never `Number()` near a figure that is stored. Parse form input with `parseMoney`/`toNumericString` from `src/app/actions/types.ts`. Display with `formatEur`/`MoneyValue`.
- Never invent financial data: a missing source renders an empty or setup state (`EmptyState`), never `0.00`.
- Every mutable entity: `id uuid default uuidv7()`, `user_id`, `version integer not null default 1`, `created_at`/`updated_at` (the application sets `updated_at`; there is no trigger). Row types exported as `typeof table.$inferSelect` from `src/lib/db/schema/<file>.ts`, re-exported from `schema/index.ts`.
- Drizzle wraps pg errors: assert on `err.cause.message`. A constraint violation caught inside an open transaction needs a savepoint (`tx.transaction(...)`), otherwise let the transaction roll back.
- Copy: all UI text, errors and docs in English. Italian appears only as data (payslip labels).
- Git: **no branches, no worktrees** (a hook blocks them). Commit on `main` after every task. Commit messages end with the executing agent's own `Co-Authored-By:` trailer. `graphify update .` runs once, in the exit-criteria task, from the repo root.
- Docs a phase must update in its exit task: `docs/architecture/overview.md` (module list + "What's deferred"), `docs/api/README.md` if routes changed, `docs/deploy/phase-N-runbook.md` (pre-checks with `pg_dump`, apply, verify, rollback), `docs/superpowers/handoff/<date>-phase-N-checkpoint.md` (state up front: implemented / deployed / not deployed, verification numbers, what remains).
- Deployment stacks: check `docs/superpowers/handoff/2026-09-05-phase-4-checkpoint.md` and the later checkpoints for which phases are deployed before writing a runbook; a phase's runbook assumes every earlier runbook has run.
